# 萤火密信中继（自建部署）

一条命令部署你自己的中继。中继只存定长密文、读后即焚、无账号体系、无日志
（代码可全文审计）。

```bash
cd relay
npm i -g wrangler   # Cloudflare 官方 CLI
wrangler login
wrangler kv namespace create BOX      # 输出 id 填入 wrangler.toml
wrangler deploy
```

部署后得到 `https://linkto-fly-relay.<你的子域>.workers.dev`，在应用
「萤火密信 → 通道」填入该地址即可。

## 它收到什么、看不到什么

| 中继可见 | 中继不可见 |
|---|---|
| 随机信箱号（16B，每封信独立生成，用完即弃） | 发件人 / 收件人身份（根本没有） |
| 定长密文（按 256B–48KB 档位填充） | 正文、主题、长度（只有档位） |
| 读取时间、IP、有效期 | 邮箱、设备、账号、公钥目录 |

两封信之间没有稳定标识：信箱号是随机的，不来自公钥、邮箱、设备或任何长期秘密。

## 三种打开方式

| 模式 | 链路上有什么 | 还需要什么 | 适合 |
|---|---|---|---|
| 一条链接 | 随机信箱号 + `#k=` 后的 256bit 密钥 | 无 | 日常，一键打开 |
| 链接 + 口令 | 随机信箱号，密钥不在链接里 | 口头/当面告你的 6 个词 | 抗网络监听，两条信道 |
| 只说口令 | 什么都没有（不发链接） | 中继网址 + 6 个词 | 对方不想装任何东西 |

6 个词来自 BIP39 词表（2048 词 × 6 = 66 bit），由客户端 CSPRNG 生成，
配合 PBKDF2-SHA256 600,000 次迭代。不是用户自选密码，因此不存在
「123456」这类可猜口令；离线暴力需要约 2^66 次带盐 KDF，不可行。

## 端点

- `POST /api/v2/box` — `{ e: "<信封 JSON>", ttl }` 投递密文；同一信箱不可覆盖
- `GET /api/v2/box/<32hex>` — 取密文（不立即删除，允许口令输错后重试；最多 8 次）
- `DELETE /api/v2/box/<32hex>` — 客户端确认解密成功后焚毁
- `GET /`、`GET /r/<32hex>` — 零安装浏览器阅读页（密钥只在 URL fragment，永不随请求发送）
- v1 的 `/api/v1/items` 保留，供旧版幽灵信使用

## 浏览器阅读页

收件人不需要安装 LinkTo：

1. 链接模式：直接打开 `https://<relay>/r/<id>#k=...`，点「打开并焚毁」。
2. 链接 + 口令：打开 `.../r/<id>#c`，输入 6 个词。
3. 纯口令：打开 `https://<relay>/`，输入 6 个词。

页面只发两种请求：读密文、删除密文。密钥不进入请求、不进入日志、不写
`localStorage`；读完后 `history.replaceState` 把 fragment 从地址栏抹掉。

页面底部显示 reader 版本与 sha256。部署后可以用 npm run fly:reader-hash 复核仓库源码的哈希，
GET /api/v2/meta 返回同一个值；对 curl 保存的原始页面，可用
npm run fly:reader-hash -- --file 保存的页面.html 复核（浏览器“另存为”会重排 HTML，不建议）。
不一致时不要输入 6 个词。

## 诚实边界

- **KV 最终一致性**：Cloudflare KV 跨 POP 不是严格一次性的。需要强一致
  「只读一次」时，把 `putBox/getBox` 换成 Durable Object（每信箱一个 DO，
  原子读删）。当前实现对并发抢读是尽力而为。
- **网页阅读页的信任**：阅读页 JS 由中继提供，理论上运营方可替换页面来窃取
  fragment 中的密钥。高敏感内容请用桌面端打开（客户端代码在本地）。
- **终端安全**：终端被木马或键盘记录器控制时，任何加密都保护不了屏幕上的
  明文。本设计只保证「链路、存储、中继」三处看不到内容。
- **流量元数据**：中继仍能看到访问时间、IP、密文档位；它不知道你是谁，但
  网络层可以观察到「某 IP 在某时刻访问了某中继」。需要隐藏这一点请叠加
  Tor / 代理。
- **口令的传递**：6 个词一旦和链接走同一条信道，就退化成单因子。请口头、
  当面或走另一条信道。

- **滥用与配额**：公开部署建议在 Cloudflare 侧加 Rate Limiting / Turnstile，或按 IP 限制投递；当前代码只限制单封信封 96KB、单信箱最多 8 次读取。
- **严格一次性**：客户端在解密成功后才发 DELETE；恶意收件人可以先取走密文再拒绝焚毁。TTL 到期仍会删除，但“只读一次”只能约束诚实客户端。
